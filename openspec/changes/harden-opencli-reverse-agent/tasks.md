## 2.0 线的现有协议回归证据

`OpenCliWsReverseAgentSessionTest` 在回环接口启动独立 WebSocket 服务，验证注册默认值、心跳、异常帧后的继续处理、collect 参数到真实子进程的传递、错误结果，以及注册前和注册后断线重连。JDK 17 `mvn -B -ntp -o clean verify` 通过 2,092 项测试，零失败、零错误、零跳过。JaCoCo XML 记录 2,806 / 3,067 行覆盖（91.49%）。准入、背压、去重、完整生命周期和三线验收仍由上面的任务跟踪。

OC-WS-001 的提前收单场景使用子进程启动标记验证。旧实现收到 `registered` 之前的 collect 后会创建标记，定向用例因此失败。修复后同一回环请求收到明确失败结果，临时目录里没有启动标记。已注册成功的收单行为继续通过回归。JDK 17 `clean verify` 共通过 2,093 项测试，零跳过，JaCoCo 行覆盖率为 2,810 / 3,071（91.50%）。

OC-WS-002 使用实际子进程启动标记验证容量。旧实现启动第五个子进程，定向用例失败。修复后默认保持四个并行任务，等待任务在释放后启动。队列容量为零和一的用例验证超额请求返回 `worker is busy`，且从未启动对应子进程。负数、零并发及溢出配置在创建客户端时拒绝。

OC-WS-006 的关闭回归先复现旧实现关闭后仍启动队列任务。关闭现在丢弃队列、请求中断在途执行，并为执行器与重连线程共用最多 5 秒等待。回归验证队列中的子进程未启动、重复关闭安全、已关闭实例拒绝重启。JDK 17 `clean verify` 通过 2,108 项测试，零跳过，行覆盖率为 2,838 / 3,095（91.70%）。完整的断线代际及三线资源回收验收仍由对应任务跟踪。

OC-WS-003/004/005 本地回环验证覆盖 128 字节请求 ID 边界、相同请求在途去重、同 ID 不同载荷拒绝、完成缓存淘汰与过期。断线测试保留真实子进程在途，验证旧结果未主动发送到新连接。经过 JVM 信任及主机名校验的 TLS 连接显式重发后得到缓存结果。明文连接按会话隔离。缓存默认保留最近 1,024 条已完成结果，每条最多 10 分钟，进程重启后重新建立去重状态。JDK 17 全量构建通过 2,113 项测试，零失败、零跳过，JaCoCo 行覆盖率为 2,891 / 3,149（91.81%）。
